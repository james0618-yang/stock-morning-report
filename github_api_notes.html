GitHub API 上传文件实战要点（含 Actions 工作流）

1. 工作流文件必须带 workflow 作用域

通过 Personal Access Token 调用 API 写入 .github/workflows/ 下的 Actions 文件时，token 必须勾选 workflow 作用域，否则接口返回 404（GitHub 故意不暴露路径是否存在）。普通仓库文件只需 repo 作用域。

2. schedule cron 使用 UTC

GitHub Actions 的 schedule.cron 按 UTC 计。北京时间 08:00 = UTC 00:00，对应 0 0 * * *。

3. 嵌套路径用 Git Data API 比 Contents API 稳

Contents API：PUT /repos/{owner}/{repo}/contents/{path} 创建 .github/workflows/xxx.yml 这类嵌套路径容易 404。

更稳做法（Git Data API）：

  1. POST /repos/{owner}/{repo}/git/blobs（base64 内容）→ 拿到 blob_sha
  2. POST /repos/{owner}/{repo}/git/trees（base_tree=当前 tree + 新文件 entry）→ 拿到 tree_sha
  3. POST /repos/{owner}/{repo}/git/commits（tree + parents=[base_sha]）→ 拿到 commit_sha
  4. PATCH /repos/{owner}/{repo}/git/refs/heads/main（sha=commit_sha）

注意：路径 URL 编码时只编码特殊字符、保留 /，否则 %2F 会导致 404。

4. Actions 工作流用内置 GITHUB_TOKEN 即可

在 workflow 中配置 permissions: contents: write，使用仓库内置 secrets.GITHUB_TOKEN，无需个人 PAT。个人 PAT 仅用于外部脚本调用 API。

5. Actions Secrets 必须用仓库公钥加密写入（不能传明文）

通过 API 写入仓库 Secret（PUT /repos/{owner}/{repo}/actions/secrets/{name}）时，不能用明文 encrypted_value，否则返回 422（"key_id" wasn't supplied）。正确流程：

  1. GET .../actions/secrets/public-key → 拿到 key（base64 公钥）与 key_id
  2. 用 libsodium sealed-box 对明文加密：SealedBox(PublicKey(key, encoder=Base64Encoder)).encrypt(value)
    • 公钥必须用 Base64Encoder 解码成原始 32 字节；直接 PublicKey(key.encode()) 会报 “must be exactly 32 bytes long”
    • Python 用 pynacl（pip install pynacl）；加密结果再 base64 编码
  3. PUT .../secrets/{name}，body 为 {"encrypted_value": <base64密文>, "key_id": <key_id>}
  4. 写入后 workflow 中通过 ${{ secrets.NAME }} 引用，凭据不落盘、不进代码。

补充：QQ 邮箱 SMTP 不能用登录密码发信，必须开启 IMAP/SMTP 服务并生成 授权码（16 位），SMTP 服务器 smtp.qq.com:465（SSL）。

适用场景

  • 无本地 git 客户端时，用 GitHub REST API 建仓 / 传文件
  • 自动生成报告并以 commit 形式回写仓库
  • 用定时任务替代本机常驻进程
